# Quality Bar

## General Standard
Done means evidence-backed, correctly routed, scoped, reviewable, and resumable without chat history.

## Governance And Documentation
- LateralLine-specific language replaces unrelated examples and generic placeholders where evidence exists.
- One owner document exists per concern; no competing project definitions are introduced.
- OBSERVED, INFERRED, PROPOSED, DECIDED, and UNKNOWN claims remain distinguishable.
- Current Git/donor state is accurate and future architecture is not represented as implemented.
- Cross-links resolve, embedded templates remain reusable, and append-only registers remain ascending/chronological.

## Implementation Work
- Scope matches the active plan and preserves explicitly protected donor behavior.
- Relevant tests and builds pass, or failures/deferred checks are recorded precisely.
- Android persistence/lifecycle changes receive focused regression coverage and appropriate physical-device validation.
- No queue/history path silently destroys persisted history unless a later explicit retention decision authorizes deletion.
- Security/privacy changes receive threat-aware review and backend authorization validation—not UI-only checks.
- Generated outputs remain non-authoritative until reconciled.

## Not Done If
- completion relies on guessed facts
- a proposal is described as already implemented
- source behavior changes without tests/review proportionate to risk
- verification is skipped without reason
- the plan/sidecar or durable docs are stale
- future work requires reconstructing intent from conversation history
